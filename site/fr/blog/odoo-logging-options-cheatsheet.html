Journaux Odoo : warn ou warning, log_level ou --log-level ? Aide-mémoire

Fichier de configuration, ligne de commande, click-odoo-update – trois écritures et trois sortes de niveaux. Un tableau à consulter et les erreurs où Odoo reste silencieusement en INFO.

Je l’oublie moi-même sans arrêt : warn ou warning ? log_level ou log-level ? La réponse dépend de l’endroit où on l’écrit. Tout sur une seule page (vérifié dans le code source d’Odoo 17).

La règle simple

  • Dans odoo.conf : tiret bas – log_level, log_handler, log_db_level.
  • En ligne de commande : tiret – --log-level, --log-handler, --log-db-level.
  • log_level accepte les mots propres à Odoo, en minuscules : warn (pas warning !), error, info, debug …
  • log_handler attend les niveaux Python en MAJUSCULES : WARNING, ERROR, DEBUG.
  • log_db_level attend les niveaux Python en minuscules : warning, error (par défaut : warning).

Valeurs autorisées

OptionValeurs
log_levelinfo (par défaut), warn, error, critical, debug, debug_sql, debug_rpc, debug_rpc_answer, notset, test, runbot
log_handlerPREFIXE:NIVEAU, niveau = DEBUG · INFO · WARNING (ou WARN) · ERROR · CRITICAL ; préfixe vide = logger racine, p. ex. :INFO
log_db_leveldebug · info · warning · error · critical
log_db%d = base courante, ou nom d’une base de journaux séparée

Exemples

click-odoo-update (et les autres scripts click-odoo) ont leurs propres options --log-level et --logfile, avec les mêmes valeurs qu’Odoo. Les réglages par logger viennent du fichier de configuration passé avec -c.

Les erreurs silencieuses

La ligne de commande refuse aussitôt une mauvaise valeur (invalid choice: 'warning'). Le fichier de configuration, non – Odoo continue simplement en INFO, et l’on s’étonne de journaux si volumineux :

log_level = warn ne règle en WARNING que les loggers odoo et werkzeug. Les bibliothèques tierces continuent d’écrire en INFO via le logger racine – pour un journal vraiment calme, ajoutez log_handler = :WARNING.
