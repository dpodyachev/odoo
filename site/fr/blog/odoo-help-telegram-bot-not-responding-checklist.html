Le bot Telegram ne répond plus : la liste de contrôle

Le bot n'envoie plus de notifications ou ne réagit plus aux commandes ? Ce qu'un utilisateur vérifie en deux minutes, ce que vérifie l'administrateur – getMe, getWebhookInfo, processus et journaux – et les causes typiques : jeton révoqué, deuxième copie avec le même jeton, groupe devenu supergroupe.

Les bots Telegram autour d'Odoo envoient des notifications (nouvelle piste, sauvegarde échouée, alarme serveur) ou répondent à des commandes. Quand l'un se tait, la cause se trouve presque toujours à l'un de trois endroits : dans Telegram (chat, droits, jeton), dans le processus du bot sur le serveur, ou dans la connexion entre les deux.

Valable pour les bots en mode polling et webhook, qu'ils tournent dans Docker, comme service systemd ou sous pm2. Le jeton est un mot de passe : il n'a sa place que dans la configuration du bot.

Vérification rapide (2 minutes, tout utilisateur)

  1. Envoyer /start ou une autre commande au bot dans un chat privé. S'il y répond, le problème est dans le groupe, pas dans le bot.
  2. Avez-vous bloqué ou mis en sourdine le bot ? Telegram ‣ chat avec le bot ‣ profil ‣ Débloquer / Réactiver le son.
  3. Groupe : le bot est-il toujours membre ? Le groupe est-il récemment devenu un supergroupe ou un forum à sujets (nouveaux admins, historique, sujets) ?
  4. Telegram fonctionne-t-il par ailleurs (autres chats) ?
  5. Quand le dernier message du bot est-il arrivé ? Cette heure réduit la recherche dans les journaux.

Pour l'administrateur

  1. getMe – le jeton est valide et le bot existe ; 401 Unauthorized signifie que le jeton a été révoqué ou régénéré dans BotFather.
  2. getWebhookInfo – avec webhook : last_error_message montre pourquoi Telegram ne peut pas livrer ; un pending_update_count qui grandit signifie que les mises à jour s'accumulent.
  3. Processus : tourne-t-il, depuis quand, redémarre-t-il en boucle ? Les 100 dernières lignes du journal montrent en général l'erreur exacte.
  4. Serveur : disque plein, mémoire épuisée, connexions sortantes vers api.telegram.org bloquées – le bot meurt en silence.
  5. Après une restauration ou une copie de test : une deuxième copie tourne-t-elle avec le même jeton ? Telegram répond alors 409 Conflict à l'une d'elles.

Causes typiques

Symptôme / messageCauseSolution
401 Unauthorizedjeton révoqué ou régénéré dans BotFathernouveau jeton dans la configuration, redémarrer le bot
409 Conflict: terminated by other getUpdates requestdeux processus interrogent avec le même jeton (ancien conteneur, copie de test, portable du développeur)arrêter le doublon ; test et stage ont leur propre jeton
400 Bad Request: chat not found / group chat was upgraded to a supergroupl'ID du chat a changé (les supergroupes commencent par -100…) ou le bot a été retirémettre à jour l'ID du chat, ajouter le bot à nouveau
403 Forbidden: bot was blocked by the userl'utilisateur a bloqué le botdébloquer et envoyer /start
429 Too Many Requeststrop de messages par seconde ou par grouperegrouper les messages, envoyer moins souvent, respecter retry_after
Webhook : last_error_message « SSL error » / « Wrong response »certificat expiré, route nginx ou port modifiérenouveler le certificat, vérifier l'URL du webhook avec curl
Aucune erreur, silenceprocessus arrêté (mémoire, disque plein, boucle de plantage) ou pas d'internet sortantrègle de redémarrage (Docker restart: unless-stopped, systemd Restart=always), supervision

Ce qu'il faut nous envoyer

  • le nom du bot (@…) et le chat ou groupe où il s'est tu – pas le jeton ;
  • quand le dernier message est arrivé et ce que le bot aurait dû envoyer ;
  • si quelque chose a changé : nouveau groupe, nouveaux admins, déménagement du serveur, restauration, mise à jour ;
  • une capture du message d'erreur, si le bot en a renvoyé un.
