Faire tourner Odoo 17 gratuitement : serveur, base de données, filestore – toutes les options et leurs pièges

Où Odoo 17 tourne gratuitement, pourquoi la base de données n’a pas sa place chez Cloudflare, comment le filestore va dans R2, et comment Cloudflare Tunnel, Access et R2 sécurisent l’ensemble.

« Puis-je faire tourner Odoo gratuitement – et mettre la base et les fichiers chez Cloudflare ? » Réponse courte : serveur oui, fichiers oui, base de données non. Voici toutes les options et leurs particularités.

En bref : Odoo + PostgreSQL ensemble dans docker compose sur Oracle Cloud Always Free (ARM, jusqu’à 24 Go de RAM). Accès via Cloudflare Tunnel, gestionnaire de bases derrière Cloudflare Access, sauvegardes et éventuellement le filestore dans Cloudflare R2.

Ce dont Odoo a besoin

  • Une application Python (odoo-bin) – en pratique 2 Go de RAM ou plus ; 1 Go avec swap suffit pour un test.
  • PostgreSQL – proche d’Odoo, idéalement sur le même serveur.
  • Un filestore – pièces jointes, images, assets. Par défaut : un répertoire sur disque (/var/lib/odoo/filestore/<db>).

Base de données : pourquoi pas chez Cloudflare

Odoo ne parle que PostgreSQL. Cloudflare ne propose pas de PostgreSQL hébergé : D1 est du SQLite, Hyperdrive est un pool de connexions pour Workers vers une base externe – aucun des deux n’aide Odoo.

Des bases externes gratuites existent, mais Odoo envoie des centaines de petites requêtes par page. Avec 20–50 ms de latence vers un autre centre de données, cela fait des secondes par clic.

Filestore : trois chemins vers R2

  1. OCA fs_storage + fs_attachment (dépôt OCA/storage, branche 17.0) : les pièces jointes sont stockées directement dans le bucket R2 (via fsspec/s3fs). Le disque du serveur ne grossit pas, les fichiers survivent à la perte du serveur. Chaque pièce jointe = un appel à R2 – les petits fichiers et assets peuvent rester en base ou sur disque ; le module le règle par type de fichier.
  2. Monter R2 comme répertoire (rclone mount, s3fs-fuse) : fonctionne, mais lent et fragile en écriture. Déconseillé en production.
  3. Filestore sur disque, sauvegarde vers R2 – le plus simple et robuste : pg_dump et rclone sync quotidiens vers le bucket. 10 Go dans R2 sont gratuits, le téléchargement (egress) ne coûte jamais rien.

Testez toujours aussi la restauration : charger le dump sur un système de stage, recopier le filestore, arrêter les tâches cron avant.

Cloudflare devant

  • Cloudflare Tunnel (gratuit) : cloudflared se connecte depuis l’intérieur – aucun port ouvert, pas besoin d’IP publique. Fonctionne aussi pour le websocket d’Odoo (/websocket).
  • Cloudflare Access : /web/database/* ou tout le système de test réservé à certaines adresses e-mail.
  • R2 : sauvegardes et filestore, compatible S3 (aws cli, rclone).
  • Mettre proxy_mode = True dans odoo.conf, sinon Odoo voit la mauvaise IP et le mauvais schéma.

Recommandation

  • Test / démo / formation : Oracle Always Free ou matériel personnel + Tunnel + Access.
  • Petite production gratuite : Oracle Always Free, mais avec sauvegarde quotidienne vers R2 et restauration testée – un compte gratuit n’a pas de SLA.
  • Production sans surprise : un petit VPS à 4–5 €/mois, sauvegardes vers R2.
  • Apps standard uniquement, sans modules personnalisés : Odoo Online « One App Free ».
