Odoo avec docker-compose : extra-addons, odoo.conf et nginx – en conteneur ou sur l’hôte

Comment monter correctement ses modules et ceux de l’OCA, ce qui doit figurer dans odoo.conf, et comment nginx relaie Odoo, websocket compris – dans les deux variantes.

Une installation Odoo avec docker-compose démarre vite – les problèmes typiques arrivent ensuite : des modules n’apparaissent pas, les modifications de configuration n’ont pas d’effet, le chat ne se connecte pas, ou Odoo devient soudain accessible directement depuis Internet. Voici une organisation qui a fait ses preuves.

Arborescence

docker-compose.yml

  • Monter des répertoires, pas des fichiers isolés. Si seul odoo.conf est monté comme fichier, le conteneur ne voit pas les modifications faites par sed -i ou par un éditeur qui réécrit le fichier – le nouveau fichier a un autre inode. Avec ./config:/etc/odoo, le problème disparaît.
  • Monter les modules en :ro : Odoo n’a pas besoin d’y écrire.
  • L’image officielle tourne sous l’utilisateur odoo (UID 101). Pour des bind mounts de données : chown -R 101:101.

odoo.conf

  • addons_path contient des chemins dans le conteneur, pas sur l’hôte.
  • Un dépôt OCA est un dossier contenant de nombreux modules – inscrivez chaque dépôt séparément. Le dossier parent oca/ seul ne suffit pas.
  • Les nouveaux modules n’apparaissent qu’après un redémarrage et « Applications → Mettre à jour la liste » (ou -u base). Sans __manifest__.py dans le dossier, ce n’est pas un module.
  • proxy_mode = True est obligatoire derrière nginx – sinon Odoo voit http au lieu de https et l’IP de nginx au lieu de celle du client.

nginx : une configuration, deux variantes

Odoo 17 a besoin de deux cibles : 8069 pour tout et 8072 pour /websocket (chat, notifications). La configuration est la même dans les deux variantes – seules les adresses upstream changent.

Variante A : nginx dans le même docker-compose

nginx joint Odoo par le nom de service odoo sur le réseau compose. Odoo ne publie aucun port – de l’extérieur, seul nginx est visible sur 80/443. Les certificats viennent de l’hôte (/etc/letsencrypt, en lecture seule).

Variante B : nginx sur l’hôte

Publier les ports d’Odoo uniquement sur 127.0.0.1 (voir les ports en commentaire ci-dessus) et pointer les upstream de nginx vers 127.0.0.1:8069 et 127.0.0.1:8072.

Attention : "8069:8069" sans 127.0.0.1 ouvre Odoo à tout Internet – même si ufw bloque le port. Docker écrit ses règles directement dans iptables, en contournant ufw.
