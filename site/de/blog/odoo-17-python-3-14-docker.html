Odoo 17 auf Python 3.14 umstellen – mit docker-compose

Eigenes Image odoo17-py314, Odoo-Quellcode aus Git in site-packages gemountet, Prüfung auf Stage und Rücksprung in einer Minute.

Ein bestehendes Odoo 17 läuft in Docker – und soll auf eine neuere Python-Version, hier 3.14. Gründe: Sicherheitsupdates des Basis-Images, neuere Bibliotheken für eigene Module, oft auch spürbar schnellere Python-Laufzeit. Odoo 17 wurde für Python 3.10–3.12 entwickelt, 3.14 ist offiziell nicht freigegeben – deshalb gilt: erst Stage, dann Produktion.

Die Idee: Image und Odoo-Code trennen

Das neue Image odoo17-py314:latest enthält nur Python 3.14 und die Abhängigkeiten. Der Odoo-Code selbst kommt aus einem Git-Checkout und wird dorthin gemountet, wo Python Pakete sucht: ./extra_addons/odoo:/usr/local/lib/python3.14/site-packages/odoo. So lassen sich Odoo-Patches per git pull einspielen, ohne das Image neu zu bauen.

Wichtig: Der Pfad enthält die Python-Version. Beim Wechsel von 3.12 auf 3.14 muss auch python3.12 → python3.14 im Volume angepasst werden – sonst findet Python das Paket odoo nicht.

Das Image

Die requirements.txt von Odoo 17 pinnt Versionen für ältere Python-Versionen. Für 3.14 werden die Pins für Pakete mit C-Erweiterungen (z. B. gevent, greenlet, lxml, psycopg2, Pillow, reportlab) auf Versionen angehoben, für die es 3.14-Wheels gibt. wkhtmltopdf (PDF-Berichte) wird wie bisher separat installiert.

Ablauf

  • Auf Stage alle wichtigen Abläufe durchklicken: Angebote, Rechnungen, Lager, PDF-Berichte, E-Mail (in den Mail-Catcher), geplante Aktionen.
  • Im Log auf ImportError, DeprecationWarning und SyntaxWarning achten – ältere Module mit ungültigen Escape-Sequenzen in Strings fallen hier zuerst auf. Seit Python 3.13 fehlen außerdem einige alte Standardmodule (PEP 594).
  • Ein Modul-Update (-u) ist für den reinen Python-Wechsel nicht nötig – das Datenbankschema ändert sich nicht.

Rücksprung

Weil Datenbank und Filestore unverändert bleiben, dauert der Rücksprung so lange wie ein Container-Neustart.
