Odoo-Logging: warn oder warning, log_level oder --log-level? Spickzettel

Konfigurationsdatei, Kommandozeile, click-odoo-update – drei Schreibweisen, drei Arten von Stufen. Eine Tabelle zum Nachschlagen und die Fehler, bei denen Odoo still auf INFO bleibt.

Ich vergesse es selbst immer wieder: Heißt es warn oder warning? log_level oder log-level? Die Antwort hängt davon ab, wo man es schreibt. Hier alles auf einer Seite (geprüft am Quellcode von Odoo 17).

Die Faustregel

  • In odoo.conf: Unterstrich – log_level, log_handler, log_db_level.
  • In der Kommandozeile: Bindestrich – --log-level, --log-handler, --log-db-level.
  • log_level kennt Odoo-eigene Wörter, klein: warn (nicht warning!), error, info, debug …
  • log_handler erwartet Python-Stufen in GROSSBUCHSTABEN: WARNING, ERROR, DEBUG.
  • log_db_level erwartet Python-Stufen klein: warning, error (Standard: warning).

Erlaubte Werte

OptionWerte
log_levelinfo (Standard), warn, error, critical, debug, debug_sql, debug_rpc, debug_rpc_answer, notset, test, runbot
log_handlerPREFIX:STUFE, Stufe = DEBUG · INFO · WARNING (oder WARN) · ERROR · CRITICAL; leerer Prefix = Root-Logger, z. B. :INFO
log_db_leveldebug · info · warning · error · critical
log_db%d = aktuelle Datenbank oder Name einer eigenen Log-Datenbank

Beispiele

click-odoo-update (und die anderen click-odoo-Skripte) haben eigene Schalter --log-level und --logfile mit denselben Werten wie Odoo. Logger-genaue Einstellungen kommen aus der mit -c übergebenen Konfigurationsdatei.

Die stillen Fehler

Die Kommandozeile meldet einen falschen Wert sofort (invalid choice: 'warning'). Die Konfigurationsdatei nicht – Odoo läuft einfach mit INFO weiter, und man wundert sich über volle Logs:

log_level = warn setzt nur die Logger odoo und werkzeug auf WARNING. Fremde Bibliotheken loggen über den Root-Logger weiter mit INFO – wer es ganz ruhig will, ergänzt log_handler = :WARNING.
