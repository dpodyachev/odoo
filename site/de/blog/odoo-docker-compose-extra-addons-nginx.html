Odoo mit docker-compose: extra-addons, odoo.conf und nginx – im Container oder auf dem Host

Wie man eigene und OCA-Module richtig einhängt, was in die odoo.conf gehört und wie nginx Odoo samt Websocket sauber weiterleitet – in beiden Varianten.

Eine Odoo-Installation mit docker-compose ist schnell gestartet – die typischen Probleme kommen danach: Module tauchen nicht auf, Änderungen an der Konfiguration wirken nicht, der Chat verbindet sich nicht, oder Odoo ist plötzlich direkt aus dem Internet erreichbar. Hier ein Aufbau, der sich bewährt hat.

Verzeichnisstruktur

docker-compose.yml

  • Verzeichnisse statt Einzeldateien mounten. Wird nur odoo.conf als Datei eingehängt, sieht der Container nach sed -i oder einem Editor, der die Datei neu schreibt, die Änderung nicht – die neue Datei hat einen anderen Inode. Mit ./config:/etc/odoo gibt es dieses Problem nicht.
  • Module :ro einhängen: Odoo braucht dort keine Schreibrechte.
  • Das offizielle Image läuft als Benutzer odoo (UID 101). Bei Bind-Mounts für Daten: chown -R 101:101.

odoo.conf

  • In addons_path stehen Pfade im Container, nicht auf dem Host.
  • Ein OCA-Repository ist ein Ordner mit vielen Modulen – jedes Repository einzeln eintragen. Der übergeordnete Ordner oca/ allein reicht nicht.
  • Neue Module erscheinen erst nach Neustart und „Apps → App-Liste aktualisieren“ (oder -u base). Ohne __manifest__.py im Modulordner ist es kein Modul.
  • proxy_mode = True ist hinter nginx Pflicht – sonst sieht Odoo http statt https und die Client-IP von nginx.

nginx: eine Konfiguration, zwei Varianten

Odoo 17 braucht zwei Ziele: 8069 für alles und 8072 für /websocket (Live-Chat, Benachrichtigungen). Die Konfiguration ist in beiden Varianten gleich – nur die upstream-Adressen unterscheiden sich.

Variante A: nginx im selben docker-compose

nginx erreicht Odoo über den Dienstnamen odoo im Compose-Netz. Odoo veröffentlicht keine Ports – von außen ist nur nginx auf 80/443 sichtbar. Zertifikate kommen vom Host (/etc/letsencrypt, schreibgeschützt).

Variante B: nginx auf dem Host

Odoo-Ports nur auf 127.0.0.1 veröffentlichen (siehe auskommentierte ports oben), in nginx upstream auf 127.0.0.1:8069 und 127.0.0.1:8072 setzen.

Achtung: "8069:8069" ohne 127.0.0.1 öffnet Odoo für das ganze Internet – auch wenn ufw den Port sperrt. Docker trägt seine Regeln direkt in iptables ein, an ufw vorbei.
