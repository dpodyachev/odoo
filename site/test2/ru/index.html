🛡️ Cloudflare Access – вход по коду из e-mail

✅ Вы вошли через Cloudflare Access. Общего пароля нет: доступ есть только у того, кто указан в политике и ввёл код из своей почты.

Что здесь происходит

  1. Cloudflare Access стоит перед сайтом. Ещё до того, как Cloudflare Pages отдаст страницу, Access проверяет, есть ли у посетителя действующая сессия.
  2. Без сессии Access перенаправляет на страницу входа команды (…cloudflareaccess.com). Там вводите e-mail и получаете одноразовый код.
  3. Политика «Owner only» разрешает ровно один адрес. Другие адреса даже не получают код.
  4. После входа Access ставит cookie на 24 часа, столько длится сессия.
  5. Защищены все адреса этой страницы: 2027.pp.ua, goldberg.pp.ua, www.goldberg.pp.ua и goldberg-odoo.pages.dev. Иначе страница была бы открыта через зеркало.
  6. В коде сайта для этого ничего нет – ни функции, ни секрета. Всё настроено в панели Zero Trust.

Когда Access, а когда Pages Functions?

СитуацияЛучше
Тестовая страница для клиента, хватит одного общего пароляBasic Auth (Pages Functions или nginx) – см. /test/
Несколько человек, у каждого свой доступ, отзывать по отдельностиCloudflare Access
Вход через Google, Microsoft, GitHub, корпоративный SSOCloudflare Access
Журнал: кто и когда входилCloudflare Access
Вся stage/тестовая система (например, Odoo stage) за входомCloudflare Access (+ origin доступен только через Cloudflare)
Машинный доступ: API, вебхуки, скриптыBasic Auth или Access с service token
Сайт не на CloudflareBasic Auth в nginx/Apache
