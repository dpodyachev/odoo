Calculator with sliders

Like pgtune – but it takes Odoo into account: Odoo's workers and memory limits decide how many connections and how much RAM PostgreSQL gets. Everything runs in your browser, nothing is sent.

Version with input fields · Version with read replica

    How it calculates

    • Workers: about 6 concurrent users per worker, at most 2 × CPU cores + 1 (on a shared server a quarter of the cores stays with PostgreSQL).
    • RAM per worker following the Odoo documentation: 80 % light requests (~150 MB), 20 % heavy (~1 GB) → about 325 MB. On a shared server PostgreSQL gets the rest, at most half of the RAM. The memory limits are ceilings for peaks (big reports, imports), not the average.
    • max_connections: Odoo processes (workers + cron + gevent) × ~3 plus a reserve – not db_maxconn × processes, which would be far too high.
    • PostgreSQL like pgtune (web/OLTP profile): shared_buffers 25 %, effective_cache_size 75 %, maintenance_work_mem 1/16 (max 2 GB), work_mem from the remaining RAM and connections.
    • On top for Odoo: jit = off, pg_stat_statements, slow query logging, earlier autovacuum.

    A starting point, not a replacement for measuring: after a week in production look at pg_stat_statements, memory and the log, and adjust.
