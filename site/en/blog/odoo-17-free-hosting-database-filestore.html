Running Odoo 17 for free: server, database, filestore – every option and its catch

Where Odoo 17 runs for free, why the database does not belong in Cloudflare, how the filestore ends up in R2, and how Cloudflare Tunnel, Access and R2 secure the setup.

“Can I run Odoo for free – and keep the database and files at Cloudflare?” Short answer: server yes, files yes, database no. Here are all the options and their quirks.

TL;DR: Odoo + PostgreSQL together in docker compose on Oracle Cloud Always Free (ARM, up to 24 GB RAM). Reachable via Cloudflare Tunnel, database manager behind Cloudflare Access, backups and optionally the filestore in Cloudflare R2.

What Odoo needs

  • A Python application (odoo-bin) – realistically 2 GB RAM or more; 1 GB with swap is enough for a test.
  • PostgreSQL – close to Odoo, ideally on the same server.
  • A filestore – attachments, images, assets. Default: a directory on disk (/var/lib/odoo/filestore/<db>).

Database: why not at Cloudflare

Odoo only speaks PostgreSQL. Cloudflare has no hosted PostgreSQL: D1 is SQLite, Hyperdrive is a connection pool for Workers to an external database – neither helps Odoo.

Free external databases exist, but Odoo sends hundreds of small queries per page. With 20–50 ms latency to another data centre that adds up to seconds per click.

Filestore: three ways to R2

  1. OCA fs_storage + fs_attachment (repository OCA/storage, branch 17.0): attachments are stored directly in the R2 bucket (via fsspec/s3fs). The server disk does not grow, files survive losing the server. Each attachment is a call to R2 – small files and assets can stay in the database or on disk; the module can control this per file type.
  2. Mount R2 as a directory (rclone mount, s3fs-fuse): works, but slow and fragile on writes. Not recommended for production.
  3. Filestore on disk, backup to R2 – simplest and robust: a daily pg_dump and rclone sync to the bucket. 10 GB in R2 are free, downloads (egress) never cost anything.

Always test the restore too: load the dump on a stage system, copy the filestore back, stop cron jobs first.

Cloudflare in front

  • Cloudflare Tunnel (free): cloudflared connects from the inside – no open ports, no public IP needed. Works for the Odoo websocket (/websocket) too.
  • Cloudflare Access: /web/database/* or the whole test system only for selected e-mail addresses.
  • R2: backups and filestore, S3-compatible (aws cli, rclone).
  • Set proxy_mode = True in odoo.conf, otherwise Odoo sees the wrong IP and scheme.

Recommendation

  • Test / demo / training: Oracle Always Free or own hardware + Tunnel + Access.
  • Small production for free: Oracle Always Free, but with daily backups to R2 and a tested restore – a free account has no SLA.
  • Production without surprises: a small VPS for €4–5/month, backups to R2.
  • Standard apps only, no custom modules: Odoo Online “One App Free”.
