Odoo logging: warn or warning, log_level or --log-level? A cheat sheet

Config file, command line, click-odoo-update – three spellings and three kinds of levels. One table to look things up, plus the mistakes where Odoo silently stays on INFO.

I keep forgetting it myself: is it warn or warning? log_level or log-level? The answer depends on where you write it. Everything on one page (checked against the Odoo 17 source).

Rule of thumb

  • In odoo.conf: underscore – log_level, log_handler, log_db_level.
  • On the command line: dash – --log-level, --log-handler, --log-db-level.
  • log_level takes Odoo's own words, lowercase: warn (not warning!), error, info, debug …
  • log_handler expects Python levels in UPPERCASE: WARNING, ERROR, DEBUG.
  • log_db_level expects Python levels in lowercase: warning, error (default: warning).

Allowed values

OptionValues
log_levelinfo (default), warn, error, critical, debug, debug_sql, debug_rpc, debug_rpc_answer, notset, test, runbot
log_handlerPREFIX:LEVEL, level = DEBUG · INFO · WARNING (or WARN) · ERROR · CRITICAL; empty prefix = root logger, e.g. :INFO
log_db_leveldebug · info · warning · error · critical
log_db%d = current database, or the name of a separate log database

Examples

click-odoo-update (and the other click-odoo scripts) have their own --log-level and --logfile switches with the same values as Odoo. Per-logger settings come from the config file passed with -c.

The silent mistakes

The command line rejects a wrong value immediately (invalid choice: 'warning'). The config file does not – Odoo simply keeps running on INFO, and you wonder why the logs are so full:

log_level = warn only sets the odoo and werkzeug loggers to WARNING. Third-party libraries keep logging at INFO via the root logger – for a really quiet log add log_handler = :WARNING.
