Leaked passwords? How to check – and how to protect Odoo against guessing, with 2FA

Where to check whether an e-mail address or password appears in data breaches without revealing the password – and what Odoo does itself: login brake, password length, two-factor login, API keys, fail2ban.

Is my address in a data breach?

  • Have I Been Pwned – enter an e-mail address and see which known breaches it appears in. For your own domains there is a domain search with notifications.
  • Mozilla Monitor – the same data, with ongoing monitoring by e-mail.
  • Google Password Checkup – checks passwords saved in Chrome / your Google account.

Is a password in leaks – without revealing it?

The Pwned Passwords API uses k-anonymity: only the first 5 characters of the SHA-1 hash are sent, the server returns all matching hash suffixes, and the comparison happens locally. The password itself never leaves your machine.

Never type passwords into random "is my password safe?" forms on the internet. The k-anonymity method above, or a password manager with a built-in breach check (Bitwarden, 1Password, KeePassXC), is safe.

Odoo: what is already built in

Login brake. After 5 failed attempts from the same IP address, Odoo waits 60 seconds before it checks the next login from there. Both values can be changed in the system parameters. The counting is per Odoo process – with several workers it is softer than the number suggests.

  • Minimum password length: module auth_password_policy (parameter above, e.g. 12).
  • Two-factor login (2FA): module auth_totp – each user enables it in their preferences with an authenticator app. With auth_totp_mail_enforce it can be enforced in General Settings: employees only or all users.
  • API keys instead of passwords for integrations (user preferences → Account Security). A key can be revoked individually, and 2FA does not block the integration.
  • Rename the admin user or use your own login – admin is the first one attackers try.

fail2ban: lock attackers out at the network level

Odoo logs every login attempt – with the IP address:

fail2ban turns this into a firewall ban. Requirements: log_level at least info (the messages are INFO) and proxy_mode = True behind nginx – otherwise the log shows nginx's IP.

Checklist

  • Database manager closed, list_db = False (see the nginx/Apache article).
  • 2FA enforced for all internal users.
  • Minimum length 12+, a password manager for the team.
  • Login brake active, plus limit_req in nginx or fail2ban.
  • Integrations with API keys, not user passwords.
  • Have your company domain monitored by Have I Been Pwned.
