Odoo with Outlook, Gmail and WhatsApp: step by step – Community and Enterprise

"CRM Outlook Integration", "kostenloses CRM für Outlook", "Odoo WhatsApp" – people want their CRM where their e-mail is. Step by step: Outlook and Gmail mailboxes in Odoo via OAuth (Azure / Google Cloud), the Odoo side panel in Outlook and Gmail, WhatsApp in Enterprise and with the OCA gateway in Community – what works on your own server, what only on odoo.com, and the traps.

Small companies in Germany live in Outlook – or Gmail – and more and more in WhatsApp. A CRM that does not see these conversations stays empty. Odoo connects to all three in two ways: as a mail server (Odoo sends and receives with your mailbox, replies land in the right lead or quote) and as a side panel in the mail client (from an e-mail, create a contact or lead in Odoo with one click).

What we tested: all modules below install in Odoo 18 Community – we installed them in our test database. The connection of real Microsoft, Google and Meta accounts follows the official Odoo and OCA documentation; we mark where something applies only to Odoo Online.

Before you start (own server)

  • HTTPS with a fixed name – Microsoft and Google only redirect to the exact address you registered. Any public HTTPS name works (your domain, or for tests a free name such as nip.io).
  • Freeze web.base.url – otherwise Odoo changes it to the address of the last admin login and the OAuth redirect stops matching.
  • Settings ‣ General Settings ‣ Emails ‣ Use Custom Email Servers – only then do the Outlook / Gmail credential fields appear.
  • Who owns the mailbox? One shared mailbox (info@, vertrieb@) for Odoo is simpler than one per user – and needs fewer rights.

Outlook / Microsoft 365 mailbox

  1. Azure: Microsoft Entra ID ‣ App registrations ‣ New: name "Odoo", account types "multitenant + personal accounts", platform Web, redirect URI as above.
  2. Permissions: API permissions ‣ Microsoft Graph ‣ Delegated: SMTP.Send, IMAP.AccessAsUser.All.
  3. Users: Enterprise application ‣ Users and groups ‣ add the users who send from Odoo.
  4. Secret: Certificates & secrets ‣ New client secret – copy the value immediately, choose the longest validity and put the expiry date in your calendar: when it expires, mail stops.
  5. Odoo: install "Microsoft Outlook"; Settings ‣ General Settings ‣ Use Custom Email Servers ‣ Outlook Credentials: Client ID and secret value.
  6. Outgoing server: Settings ‣ Technical ‣ Outgoing Mail Servers ‣ New ‣ Outlook, user name, "From" filter (your domain) ‣ Connect your Outlook account ‣ Test Connection.
  7. Incoming server: Settings ‣ Technical ‣ Incoming Mail Servers ‣ New ‣ Outlook OAuth Authentication ‣ connect ‣ test. Replies to Odoo e-mails now land in the right lead or quote.

Gmail / Google Workspace mailbox

  1. Google Cloud: new project "Odoo"; OAuth consent screen: Internal (Workspace) or External (personal Gmail); with External in testing mode add the mailbox as Test user.
  2. Credentials ‣ Create credentials ‣ OAuth client ID ‣ type Web application (not Desktop – that gives "redirect_uri_mismatch") ‣ redirect URI as above.
  3. Odoo: install "Google Gmail"; Settings ‣ General Settings ‣ Use Custom Email Servers ‣ Gmail Credentials: Client ID and secret.
  4. Outgoing server: New ‣ Gmail OAuth Authentication ‣ Connect your Gmail account ‣ "Gmail Token Valid" ‣ Test Connection.
  5. Incoming server: same with Gmail OAuth on the incoming server.
  6. 403 access denied usually means the mailbox is not in the test users; "Production" status brings the 100-logins limit warning – Odoo recommends staying in testing.

The side panel: Outlook and Gmail plugin

The plugin shows the Odoo contact, company, open leads and tickets next to an e-mail and creates a lead from it with one click. Odoo side: Settings ‣ General Settings ‣ Integrations ‣ Mail Plugin (install crm_mail_plugin for leads).

  • Outlook: the add-in is installed from the manifest file and then logs in to your database URL – this also works for an own server with HTTPS. If the panel stays empty, the browser blocks third-party cookies: allow cookies for download.odoo.com.
  • Gmail: the "Odoo Inbox Addin" in the Google Workspace Marketplace only connects to *.odoo.com. For an own server you have to take the plugin from Odoo's GitHub repository mail-client-extensions, change the allowed domain to yours and publish it as your own Google Apps Script project – doable, but a small project of its own.
  • Company insights (enrichment of the company from the e-mail domain) need paid IAP credits; the rest of the plugin does not.

WhatsApp

WhatsApp in Odoo goes through Meta's WhatsApp Business Platform (the API) – not the WhatsApp Business app on the phone. Requirements in both editions: a Meta Business account, a Meta developer app with the WhatsApp product, a phone number registered there, and approved message templates for messages the company starts. Meta charges per conversation according to its own price list.

  • Enterprise: the WhatsApp app – WhatsApp ‣ Configuration ‣ WhatsApp Business Accounts: Phone Number ID, access token, App ID, Account ID, App Secret ‣ Test Connection; copy callback URL and verify token into Meta's webhook settings; sync templates. Send quotes, invoices and reminders by WhatsApp from Odoo.
  • Community: OCA mail_gateway_whatsapp (OCA/social, branch 18.0): Settings ‣ Emails ‣ Mail Gateway ‣ new gateway of type WhatsApp with token, phone number ID and secret; the webhook is entered in Meta by hand. Chats then run in Odoo Discuss – fewer comfort functions than Enterprise, no licence.
  • Your server must be reachable from Meta (webhook over HTTPS).
  • GDPR: business messages run via Meta; you need the customer's consent for WhatsApp and a data processing agreement with Meta (WhatsApp Business terms). Clarify this before the first message.

Traps

  • web.base.url changed → OAuth error "redirect URI mismatch" after an admin logged in via another address. Freeze it.
  • Expired client secret (Azure) → mail silently stops. Calendar entry, monitoring of the mail queue.
  • From filter / sender address: Microsoft 365 and Gmail only send as the connected mailbox (or allowed aliases). Set the outgoing server's "From" filter and the default sender accordingly, otherwise mails bounce.
  • Personal vs shared mailbox: per-user servers need settings rights for those users and a fallback server for notifications – start with one shared mailbox.
  • Gmail plugin on own server – plan it as a small project, not a click.
  • WhatsApp – without approved templates you can only answer within 24 hours after the customer's last message.

Conclusion

Outlook and Gmail as mail servers and the Outlook panel work fully in Odoo Community on your own server; the Gmail panel needs some extra work there, WhatsApp is built into Enterprise and available in Community via OCA. The order we recommend: freeze the address, connect one shared mailbox, set up the lead alias, then the plugin for the sales team, WhatsApp last. We set this up for companies in Germany, Austria and Switzerland and can show it on a test database first.
