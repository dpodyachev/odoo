Password protection with nginx and Apache – and what to close in Odoo

HTTP Basic Auth with htpasswd in nginx and Apache, IP allow-lists, and the Odoo URLs that should not be public: database manager, database selector, /website/info – plus list_db and a login brake.

Basic Auth in 3 minutes

The web server asks for a user name and password before the request even reaches the application. Simple, robust and well suited for admin areas, test systems and internal pages. Important: HTTPS only – otherwise credentials travel in plain text.

Try it: https://2027.pp.ua/test/ is protected the same way – here via Cloudflare Pages Functions, because this website is static. User name and password are stored as a secret at Cloudflare, not in the Git repository.

What should not be public in Odoo

URLWhat is thereRecommendation
/web/database/managerdatabase manager: create, duplicate, drop, back up, restoreclose (IP + password) and list_db = False
/web/database/selectorlist of all databasesclose
/web/database/* (create, drop, backup, restore, duplicate, change_password, list)the actions behind it, protected only by the master passwordclose; with list_db = False Odoo refuses them
/website/infoinstalled apps and version (website module)404 from outside
/web/loginloginkeep open, but slow it down (see below)
/xmlrpc/2/*, /jsonrpcAPI for integrationsopen only if integrations need it – then with API keys instead of passwords

The database manager is the most dangerous spot: with the master password anyone can download or delete the whole database there. It never belongs on the internet unprotected.

And in Odoo itself

  • list_db = False switches database management off – Odoo then refuses create, drop, backup and restore via web and RPC. Backups are better done with pg_dump on the server anyway.
  • A strong admin_passwd is still a must.
  • Without proxy_mode = True, Odoo behind nginx only sees nginx's IP – then neither the login brake nor fail2ban work properly.
