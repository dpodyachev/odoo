Odoo with docker-compose: extra-addons, odoo.conf and nginx – in a container or on the host

How to mount your own and OCA modules correctly, what belongs in odoo.conf, and how nginx proxies Odoo including the websocket – in both variants.

An Odoo installation with docker-compose starts quickly – the typical problems come afterwards: modules don't show up, config changes have no effect, the chat won't connect, or Odoo is suddenly reachable directly from the internet. Here is a setup that has proven itself.

Directory layout

docker-compose.yml

  • Mount directories, not single files. If only odoo.conf is mounted as a file, the container won't see changes made by sed -i or an editor that rewrites the file – the new file has a different inode. With ./config:/etc/odoo that problem is gone.
  • Mount modules :ro: Odoo needs no write access there.
  • The official image runs as user odoo (UID 101). For bind mounts with data: chown -R 101:101.

odoo.conf

  • addons_path contains paths inside the container, not on the host.
  • An OCA repository is a folder with many modules – list each repository separately. The parent folder oca/ alone is not enough.
  • New modules appear only after a restart and "Apps → Update Apps List" (or -u base). Without __manifest__.py in the folder it is not a module.
  • proxy_mode = True is mandatory behind nginx – otherwise Odoo sees http instead of https and nginx's IP instead of the client's.

nginx: one config, two variants

Odoo 17 needs two targets: 8069 for everything and 8072 for /websocket (live chat, notifications). The config is the same in both variants – only the upstream addresses differ.

Variant A: nginx in the same docker-compose

nginx reaches Odoo via the service name odoo on the compose network. Odoo publishes no ports – from outside only nginx on 80/443 is visible. Certificates come from the host (/etc/letsencrypt, read-only).

Variant B: nginx on the host

Publish the Odoo ports on 127.0.0.1 only (see the commented-out ports above), and point the nginx upstream to 127.0.0.1:8069 and 127.0.0.1:8072.

Warning: "8069:8069" without 127.0.0.1 opens Odoo to the whole internet – even if ufw blocks the port. Docker writes its rules straight into iptables, bypassing ufw.
