Moving Odoo 17 to Python 3.14 – with docker-compose

A custom odoo17-py314 image, Odoo source from Git mounted into site-packages, testing on stage and a one-minute rollback.

An existing Odoo 17 runs in Docker and should move to a newer Python, here 3.14. Reasons: security updates of the base image, newer libraries for custom modules, and often a noticeably faster Python runtime. Odoo 17 was built for Python 3.10–3.12; 3.14 is not officially supported – so the rule is stage first, production second.

The idea: separate the image from the Odoo code

The new image odoo17-py314:latest only contains Python 3.14 and the dependencies. The Odoo code comes from a Git checkout and is mounted where Python looks for packages: ./extra_addons/odoo:/usr/local/lib/python3.14/site-packages/odoo. Odoo patches are then a git pull away, without rebuilding the image.

Important: the path contains the Python version. When moving from 3.12 to 3.14, change python3.12 → python3.14 in the volume too – otherwise Python will not find the odoo package.

The image

Odoo 17's requirements.txt pins versions for older Pythons. For 3.14, raise the pins of packages with C extensions (e.g. gevent, greenlet, lxml, psycopg2, Pillow, reportlab) to versions that ship 3.14 wheels. wkhtmltopdf (PDF reports) is installed separately as before.

Procedure

  • On stage, click through all key flows: quotations, invoices, inventory, PDF reports, e-mail (into a mail catcher), scheduled actions.
  • Watch the log for ImportError, DeprecationWarning and SyntaxWarning – older modules with invalid escape sequences in strings show up here first. Since Python 3.13 some old standard modules are gone as well (PEP 594).
  • A module update (-u) is not needed for a pure Python switch – the database schema does not change.

Rollback

Database and filestore stay untouched, so a rollback takes as long as a container restart.
