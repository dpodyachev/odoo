Μετάβαση του Odoo 17 σε Python 3.14 – με docker-compose

Δικό μας image odoo17-py314, ο κώδικας του Odoo από το Git προσαρτημένος στο site-packages, δοκιμή στο stage και επαναφορά σε ένα λεπτό.

Ένα υπάρχον Odoo 17 τρέχει σε Docker και πρέπει να περάσει σε νεότερη Python, εδώ 3.14. Γιατί: ενημερώσεις ασφαλείας του βασικού image, νεότερες βιβλιοθήκες για τα δικά μας modules και συχνά αισθητά ταχύτερη Python. Το Odoo 17 σχεδιάστηκε για Python 3.10–3.12· η 3.14 δεν υποστηρίζεται επίσημα – άρα ο κανόνας είναι: πρώτα stage, μετά παραγωγή.

Η ιδέα: χωρίζουμε το image από τον κώδικα του Odoo

Το νέο image odoo17-py314:latest περιέχει μόνο την Python 3.14 και τις εξαρτήσεις. Ο κώδικας του Odoo έρχεται από ένα Git checkout και προσαρτάται εκεί όπου η Python αναζητά πακέτα: ./extra_addons/odoo:/usr/local/lib/python3.14/site-packages/odoo. Έτσι οι διορθώσεις του Odoo περνούν με ένα git pull, χωρίς νέο build του image.

Σημαντικό: η διαδρομή περιέχει την έκδοση της Python. Στη μετάβαση από 3.12 σε 3.14 αλλάξτε και στο volume python3.12 → python3.14 – αλλιώς η Python δεν βρίσκει το πακέτο odoo.

Το image

Το requirements.txt του Odoo 17 «κλειδώνει» εκδόσεις για παλαιότερες Python. Για την 3.14 ανεβάζουμε τις εκδόσεις των πακέτων με επεκτάσεις C (π.χ. gevent, greenlet, lxml, psycopg2, Pillow, reportlab) σε εκείνες που έχουν wheels για 3.14. Το wkhtmltopdf (αναφορές PDF) εγκαθίσταται ξεχωριστά, όπως πριν.

Διαδικασία

  • Στο stage περνάμε όλες τις βασικές ροές: προσφορές, τιμολόγια, αποθήκη, αναφορές PDF, e-mail (σε mail catcher), προγραμματισμένες ενέργειες.
  • Στο log προσέχουμε ImportError, DeprecationWarning και SyntaxWarning – παλιά modules με μη έγκυρες ακολουθίες διαφυγής σε συμβολοσειρές εμφανίζονται πρώτα. Από την Python 3.13 λείπουν επίσης ορισμένα παλιά πρότυπα modules (PEP 594).
  • Ενημέρωση modules (-u) δεν χρειάζεται για σκέτη αλλαγή Python – το σχήμα της βάσης δεν αλλάζει.

Επαναφορά

Η βάση και το filestore μένουν ανέγγιχτα, οπότε η επαναφορά διαρκεί όσο μια επανεκκίνηση container.
