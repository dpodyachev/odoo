Διέρρευσαν κωδικοί; Πώς ελέγχετε – και πώς προστατεύετε το Odoo από δοκιμές κωδικών, με 2FA

Πού ελέγχετε αν ένα e-mail ή ένας κωδικός εμφανίζεται σε διαρροές χωρίς να αποκαλύψετε τον κωδικό – και τι κάνει το ίδιο το Odoo: φρένο σύνδεσης, ελάχιστο μήκος, σύνδεση δύο παραγόντων, API keys, fail2ban.

Υπάρχει η διεύθυνσή μου σε διαρροή;

  • Have I Been Pwned – εισάγετε e-mail και βλέπετε σε ποιες γνωστές διαρροές εμφανίζεται. Για δικά σας domains υπάρχει αναζήτηση ανά domain με ειδοποιήσεις.
  • Mozilla Monitor – τα ίδια δεδομένα, με συνεχή παρακολούθηση μέσω e-mail.
  • Google Password Checkup – ελέγχει κωδικούς αποθηκευμένους στον Chrome / στον λογαριασμό Google.

Υπάρχει ένας κωδικός σε διαρροές – χωρίς να τον αποκαλύψω;

Το API του Pwned Passwords λειτουργεί με k-ανωνυμία: στέλνονται μόνο οι πρώτοι 5 χαρακτήρες του SHA-1 hash, ο server επιστρέφει όλες τις καταλήξεις που ταιριάζουν και η σύγκριση γίνεται τοπικά. Ο ίδιος ο κωδικός δεν φεύγει ποτέ από τον υπολογιστή σας.

Μην πληκτρολογείτε ποτέ κωδικούς σε τυχαίες φόρμες «είναι ασφαλής ο κωδικός μου;» στο internet. Ασφαλή είναι η μέθοδος k-ανωνυμίας παραπάνω ή ένας password manager με ενσωματωμένο έλεγχο διαρροών (Bitwarden, 1Password, KeePassXC).

Odoo: τι είναι ήδη ενσωματωμένο

Φρένο σύνδεσης. Μετά από 5 αποτυχημένες προσπάθειες από την ίδια IP, το Odoo περιμένει 60 δευτερόλεπτα πριν ελέγξει την επόμενη σύνδεση από εκεί. Και οι δύο τιμές αλλάζουν στις παραμέτρους συστήματος. Η μέτρηση γίνεται ανά διεργασία Odoo – με πολλούς workers είναι πιο χαλαρή απ' ό,τι δείχνει ο αριθμός.

  • Ελάχιστο μήκος κωδικού: module auth_password_policy (παράμετρος παραπάνω, π.χ. 12).
  • Σύνδεση δύο παραγόντων (2FA): module auth_totp – κάθε χρήστης την ενεργοποιεί στις προτιμήσεις του με μια εφαρμογή authenticator. Με το auth_totp_mail_enforce μπορεί να γίνει υποχρεωτική στις γενικές ρυθμίσεις: μόνο για υπαλλήλους ή για όλους.
  • API keys αντί για κωδικούς στις διασυνδέσεις (προτιμήσεις χρήστη → Ασφάλεια λογαριασμού). Ένα key ανακαλείται μεμονωμένα και το 2FA δεν μπλοκάρει τη διασύνδεση.
  • Μετονομάστε τον χρήστη admin ή χρησιμοποιήστε δικό σας login – το admin δοκιμάζεται πρώτο.

fail2ban: αποκλεισμός επιτιθέμενων σε επίπεδο δικτύου

Το Odoo καταγράφει κάθε προσπάθεια σύνδεσης – μαζί με τη διεύθυνση IP:

Το fail2ban το μετατρέπει σε αποκλεισμό στο firewall. Προϋποθέσεις: log_level τουλάχιστον info (τα μηνύματα είναι επιπέδου INFO) και proxy_mode = True πίσω από nginx – αλλιώς το log δείχνει την IP του nginx.

Λίστα ελέγχου

  • Διαχείριση βάσεων κλειστή, list_db = False (βλ. άρθρο για nginx/Apache).
  • 2FA υποχρεωτικό για όλους τους εσωτερικούς χρήστες.
  • Ελάχιστο μήκος 12+, password manager για την ομάδα.
  • Φρένο σύνδεσης ενεργό, συν limit_req στον nginx ή fail2ban.
  • Διασυνδέσεις με API keys, όχι με κωδικούς χρηστών.
  • Παρακολούθηση του domain της εταιρείας από το Have I Been Pwned.

Εργαλεία και τεκμηρίωση

  • Have I Been Pwned
  • Pwned Passwords API (k-anonymity)
  • Mozilla Monitor
  • Google Password Checkup
  • Odoo 17: Two-factor authentication
