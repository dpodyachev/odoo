Odoo у docker-compose: extra-addons, odoo.conf і nginx – у контейнері чи на хості

Як правильно змонтувати власні й OCA-модулі, що має бути в odoo.conf і як nginx коректно проксить Odoo разом із websocket – в обох варіантах.

Odoo в docker-compose запускається швидко, а типові проблеми починаються потім: модулі не з'являються, зміни конфігу не діють, чат не підключається, або Odoo раптом доступний напряму з інтернету. Ось схема, яка себе виправдала.

Структура каталогів

docker-compose.yml

  • Монтуйте каталоги, а не окремі файли. Якщо змонтовано лише файл odoo.conf, контейнер не побачить змін після sed -i або редактора, який перезаписує файл: у нового файлу інший inode. З ./config:/etc/odoo цієї проблеми немає.
  • Модулі монтуйте з :ro: Odoo не потрібні права на запис туди.
  • Офіційний образ працює від користувача odoo (UID 101). Для bind-mount з даними: chown -R 101:101.

odoo.conf

  • В addons_path пишуться шляхи всередині контейнера, а не на хості.
  • OCA-репозиторій – це каталог із багатьма модулями. Кожен репозиторій треба вказати окремо, батьківського oca/ недостатньо.
  • Нові модулі з'являються лише після перезапуску й «Додатки → Оновити список» (або -u base). Без __manifest__.py у каталозі це не модуль.
  • proxy_mode = True за nginx обов'язковий, інакше Odoo бачить http замість https і IP nginx замість клієнта.

nginx: один конфіг, два варіанти

Odoo 17 потрібні дві адреси: 8069 для всього і 8072 для /websocket (чат, сповіщення). Конфіг однаковий в обох варіантах, відрізняються лише адреси в upstream.

Варіант А: nginx у тому самому docker-compose

nginx звертається до Odoo за іменем сервісу odoo у мережі compose. Odoo не публікує порти, ззовні видно лише nginx на 80/443. Сертифікати беруться з хоста (/etc/letsencrypt, лише читання).

Варіант Б: nginx на хості

Порти Odoo публікуються лише на 127.0.0.1 (див. закоментовані ports вище), а в upstream nginx вказуються 127.0.0.1:8069 і 127.0.0.1:8072.

Увага: "8069:8069" без 127.0.0.1 відкриває Odoo всьому інтернету, навіть якщо ufw блокує порт. Docker пише свої правила прямо в iptables, повз ufw.
