Cloudflare Access (Zero Trust) покроково – і коли це краще за пароль

Вхід за кодом з e-mail або через SSO перед будь-яким сайтом чи тестовою системою – без жодного рядка коду. Налаштування в п'ять кроків, порівняння з Basic Auth через Pages Functions, пастки та практика з Odoo.

На цьому сайті є дві демо-сторінки з однаковим вмістом і різним захистом: /test/ із Basic Auth через Cloudflare Pages Functions (один спільний пароль, який перевіряє невелика функція) і /test2/ із Cloudflare Access (особистий вхід за кодом з e-mail). Ця стаття пояснює Access і коли що обирати.

Що таке Cloudflare Access?

Access – частина Cloudflare Zero Trust. Він стоїть перед сайтом чи застосунком і пропускає лише тих, хто увійшов і кому це дозволяє політика. Увійти можна за одноразовим кодом на e-mail, через Google, Microsoft, GitHub або корпоративний SSO. Безкоштовний тариф – до 50 користувачів.

Access чи Basic Auth?

Basic Auth (Pages Functions / nginx)Cloudflare Access
Доступодин спільний парольособистий: за e-mail, групою або доменом
Забрати доступ у когосьзмінити пароль для всіхвидалити одну адресу з політики
Вхідвікно браузера, паролькод на e-mail, Google, Microsoft, GitHub, SSO
Журналнемаєє: хто й коли входив
Код на сайтіфункція + секрет (/test/) або конфіг nginxжодного – усе в панелі
Машини (API, вебхуки)просто: логін/пароль у заголовкупотрібен service token
Умованемаєдомен або Pages-проєкт в акаунті Cloudflare

Просте правило: один пароль на кількох людей – Basic Auth. Люди, ролі, журнал, SSO – Access.

Налаштування в п'ять кроків

  1. Увімкнути Zero Trust. dash.cloudflare.com → Zero Trust → вибрати назву команди (з неї буде <team>.cloudflareaccess.com) → тариф Free. Cloudflare може попросити картку, але Free нічого не коштує.
  2. Спосіб входу. Zero Trust → Settings → Authentication → Login methods → додати «One-time PIN». За бажанням – Google, Microsoft або GitHub.
  3. Створити застосунок. Access → Applications → Add → Self-hosted. Вказати домен і шлях, наприклад 2027.pp.ua + test2. Вибрати тривалість сесії (тут 24 год).
  4. Політика. Action «Allow», Include → «Emails» (окремі адреси) або «Emails ending in» (наприклад @firma.ua). Без відповідної політики ніхто не ввійде.
  5. Захистити всі адреси. Та сама сторінка часто доступна під кількома іменами: власний домен, дзеркала, project.pages.dev. Кожне додайте як ще одне призначення (destination) застосунку.

Саме крок 5 найчастіше забувають: у демо /test2/ сторінку спершу захистили лише на 2027.pp.ua, а через goldberg.pp.ua і goldberg-odoo.pages.dev вона була б відкрита. Тому завжди перевіряйте всі імена хостів.

Перевірка

Вихід – за фіксованою адресою:

Access перед Odoo

  • Stage і тестові системи повністю за Access: клієнти й тестувальники входять зі своїм e-mail, без зайвих облікових записів Odoo назовні.
  • Менеджер баз (/web/database/*) на проді: окремий застосунок Access лише для цього шляху, доступ лише адміністраторам.
  • API, вебхуки, мобільний застосунок не можуть пройти інтерактивний вхід: для цих шляхів – політика «Bypass» або service token.
  • Важливо: Access захищає лише шлях через Cloudflare. Якщо сервер Odoo доступний напряму за IP, захист обходиться. Відкрийте фаєрвол лише для IP Cloudflare або використайте Cloudflare Tunnel і перевіряйте заголовок Cf-Access-Jwt-Assertion.
