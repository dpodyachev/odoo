Перехід Odoo 17 на Python 3.14 у docker-compose

Власний образ odoo17-py314, код Odoo з Git змонтовано в site-packages, перевірка на stage і відкат за хвилину.

Наявний Odoo 17 працює в Docker, і його треба перевести на новіший Python, тут 3.14. Навіщо: оновлення безпеки базового образу, свіжі бібліотеки для власних модулів, часто помітно швидший Python. Odoo 17 розроблявся під Python 3.10–3.12, 3.14 офіційно не підтримується. Тому правило: спершу stage, потім прод.

Ідея: розділити образ і код Odoo

Новий образ odoo17-py314:latest містить лише Python 3.14 і залежності. Код Odoo береться з Git-репозиторію і монтується туди, де Python шукає пакети: ./extra_addons/odoo:/usr/local/lib/python3.14/site-packages/odoo. Патчі Odoo тоді ставляться через git pull, без перезбирання образу.

Важливо: у шляху є версія Python. При переході з 3.12 на 3.14 змініть у volume python3.12 → python3.14, інакше Python не знайде пакет odoo.

Образ

requirements.txt в Odoo 17 фіксує версії для старіших Python. Для 3.14 піднімаємо версії пакетів із C-розширеннями (gevent, greenlet, lxml, psycopg2, Pillow, reportlab тощо) до тих, що мають wheels для 3.14. wkhtmltopdf (PDF-звіти) ставиться окремо, як і раніше.

Порядок дій

  • На stage пройти всі ключові процеси: пропозиції, рахунки, склад, PDF-звіти, пошта (у mail catcher), заплановані дії.
  • У лозі стежити за ImportError, DeprecationWarning і SyntaxWarning. Старі модулі з некоректними escape-послідовностями в рядках вилізуть першими. З Python 3.13 також прибрано кілька старих стандартних модулів (PEP 594).
  • Оновлення модулів (-u) для самої зміни Python не потрібне: схема бази не змінюється.

Відкат

База і filestore не змінюються, тому відкат триває стільки ж, скільки перезапуск контейнера.
