Паролі витекли? Як перевірити – і як захистити Odoo від перебору, з 2FA

Де перевірити, чи є e-mail і пароль у витоках, не розкриваючи сам пароль, і що вміє сам Odoo: гальмо логіну, довжина пароля, двофакторний вхід, API-ключі, fail2ban.

Чи є моя адреса у витоку?

  • Have I Been Pwned – вводите e-mail і бачите, у яких відомих витоках він є. Для власних доменів є пошук за доменом зі сповіщеннями.
  • Mozilla Monitor – ті самі дані з постійним моніторингом поштою.
  • Google Password Checkup – перевіряє паролі, збережені в Chrome / акаунті Google.

Чи є пароль у витоках – не розкриваючи його?

API Pwned Passwords працює за принципом k-анонімності: надсилаються лише перші 5 символів SHA-1-хешу, сервер повертає всі закінчення хешів із цим початком, а порівняння відбувається локально. Сам пароль ніколи не покидає комп'ютер.

Ніколи не вводьте паролі в будь-які форми «чи надійний мій пароль?» в інтернеті. Безпечні – метод k-анонімності вище або менеджер паролів із вбудованою перевіркою витоків (Bitwarden, 1Password, KeePassXC).

Odoo: що вже вбудовано

Гальмо логіну. Після 5 невдалих спроб з однієї IP-адреси Odoo чекає 60 секунд, перш ніж перевірити наступний вхід звідти. Обидва значення змінюються в системних параметрах. Лічильник ведеться окремо в кожному процесі Odoo, тож за кількох воркерів захист м'якший, ніж здається з цифри.

  • Мінімальна довжина пароля: модуль auth_password_policy (параметр вище, наприклад 12).
  • Двофакторний вхід (2FA): модуль auth_totp – кожен користувач вмикає його у своїх налаштуваннях через застосунок-автентифікатор. З auth_totp_mail_enforce його можна зробити обов'язковим у загальних налаштуваннях: лише для співробітників або для всіх.
  • API-ключі замість паролів для інтеграцій (налаштування користувача → Безпека облікового запису). Ключ можна відкликати окремо, і 2FA не блокує інтеграцію.
  • Перейменуйте користувача admin або використовуйте власний логін: admin перебирають першим.

fail2ban: блокувати атакувальників на рівні мережі

Odoo пише в лог кожну спробу входу разом з IP-адресою:

fail2ban перетворює це на блокування у фаєрволі. Умови: log_level не нижче info (ці повідомлення мають рівень INFO) і proxy_mode = True за nginx, інакше в лозі буде IP nginx.

Чек-лист

  • Менеджер баз закрито, list_db = False (див. статтю про nginx/Apache).
  • 2FA обов'язкова для всіх внутрішніх користувачів.
  • Мінімальна довжина 12+, менеджер паролів для команди.
  • Гальмо логіну ввімкнено, плюс limit_req у nginx або fail2ban.
  • Інтеграції – з API-ключами, а не з паролями користувачів.
  • Домен компанії – під моніторингом Have I Been Pwned.

Інструменти та документація

  • Have I Been Pwned
  • Pwned Passwords API (k-anonymity)
  • Mozilla Monitor
  • Google Password Checkup
  • Odoo 17: Two-factor authentication
