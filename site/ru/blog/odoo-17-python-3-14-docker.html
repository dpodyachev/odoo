Перевод Odoo 17 на Python 3.14 в docker-compose

Свой образ odoo17-py314, код Odoo из Git смонтирован в site-packages, проверка на stage и откат за минуту.

Существующий Odoo 17 работает в Docker, и его нужно перевести на более новый Python, здесь 3.14. Зачем: обновления безопасности базового образа, свежие библиотеки для собственных модулей, часто заметно более быстрый Python. Odoo 17 разрабатывался под Python 3.10–3.12, 3.14 официально не поддерживается. Поэтому правило: сначала stage, потом прод.

Идея: разделить образ и код Odoo

Новый образ odoo17-py314:latest содержит только Python 3.14 и зависимости. Код Odoo берётся из Git-репозитория и монтируется туда, где Python ищет пакеты: ./extra_addons/odoo:/usr/local/lib/python3.14/site-packages/odoo. Патчи Odoo тогда ставятся через git pull, без пересборки образа.

Важно: в пути есть версия Python. При переходе с 3.12 на 3.14 поменяйте в volume python3.12 → python3.14, иначе Python не найдёт пакет odoo.

Образ

requirements.txt в Odoo 17 фиксирует версии для старых Python. Для 3.14 поднимаем версии пакетов с C-расширениями (gevent, greenlet, lxml, psycopg2, Pillow, reportlab и др.) до тех, у которых есть wheels под 3.14. wkhtmltopdf (PDF-отчёты) ставится отдельно, как и раньше.

Порядок действий

  • На stage пройти все ключевые процессы: предложения, счета, склад, PDF-отчёты, почта (в mail catcher), запланированные действия.
  • В логе следить за ImportError, DeprecationWarning и SyntaxWarning. Старые модули с некорректными escape-последовательностями в строках вылезут первыми. С Python 3.13 также убрано несколько старых стандартных модулей (PEP 594).
  • Обновление модулей (-u) для самой смены Python не нужно: схема базы не меняется.

Откат

База и filestore не меняются, поэтому откат занимает столько же, сколько перезапуск контейнера.
