Cloudflare Access (Zero Trust) по шагам – и когда это лучше пароля

Вход по коду из e-mail или через SSO перед любым сайтом или тестовой системой – без единой строки кода. Настройка в пять шагов, сравнение с Basic Auth через Pages Functions, ловушки и практика с Odoo.

На этом сайте есть две демо-страницы с одинаковым содержимым и разной защитой: /test/ с Basic Auth через Cloudflare Pages Functions (один общий пароль, его проверяет небольшая функция) и /test2/ с Cloudflare Access (личный вход по коду из e-mail). Эта статья объясняет Access и когда что выбирать.

Что такое Cloudflare Access?

Access – часть Cloudflare Zero Trust. Он стоит перед сайтом или приложением и пропускает только тех, кто вошёл и кому это разрешает политика. Войти можно по одноразовому коду на e-mail, через Google, Microsoft, GitHub или корпоративный SSO. Бесплатный тариф – до 50 пользователей.

Простое правило: один пароль на несколько человек – Basic Auth. Люди, роли, журнал, SSO – Access.

Настройка в пять шагов

  1. Включить Zero Trust. dash.cloudflare.com → Zero Trust → выбрать имя команды (из него будет <team>.cloudflareaccess.com) → тариф Free. Cloudflare может попросить карту, но Free ничего не стоит.
  2. Способ входа. Zero Trust → Settings → Authentication → Login methods → добавить «One-time PIN». По желанию – Google, Microsoft или GitHub.
  3. Создать приложение. Access → Applications → Add → Self-hosted. Указать домен и путь, например 2027.pp.ua + test2. Выбрать длительность сессии (здесь 24 ч).
  4. Политика. Action «Allow», Include → «Emails» (отдельные адреса) или «Emails ending in» (например @firma.ru). Без подходящей политики никто не войдёт.
  5. Защитить все адреса. Одна и та же страница часто доступна под несколькими именами: свой домен, зеркала, project.pages.dev. Каждое добавьте как ещё одно назначение (destination) приложения.

Именно шаг 5 чаще всего забывают: в демо /test2/ страницу сначала защитили только на 2027.pp.ua, а через goldberg.pp.ua и goldberg-odoo.pages.dev она была бы открыта. Поэтому всегда проверяйте все имена хостов.

Access перед Odoo

  • Stage и тестовые системы целиком за Access: клиенты и тестировщики входят со своим e-mail, без лишних учётных записей Odoo наружу.
  • Менеджер баз (/web/database/*) на проде: отдельное приложение Access только для этого пути, доступ только администраторам.
  • API, вебхуки, мобильное приложение не могут пройти интерактивный вход: для этих путей – политика «Bypass» или service token.
  • Важно: Access защищает только путь через Cloudflare. Если сервер Odoo доступен напрямую по IP, защита обходится. Откройте файрвол только для IP Cloudflare или используйте Cloudflare Tunnel и проверяйте заголовок Cf-Access-Jwt-Assertion.
