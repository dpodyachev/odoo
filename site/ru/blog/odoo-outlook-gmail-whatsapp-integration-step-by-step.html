Odoo с Outlook, Gmail и WhatsApp: пошагово – Community и Enterprise

«CRM Outlook Integration», «kostenloses CRM für Outlook», «Odoo WhatsApp» – CRM хотят там, где почта. Пошагово: ящики Outlook и Gmail в Odoo через OAuth (Azure / Google Cloud), боковая панель Odoo в Outlook и Gmail, WhatsApp в Enterprise и через шлюз OCA в Community – что работает на своём сервере, что только на odoo.com, и ловушки.

Маленькие фирмы в Германии живут в Outlook – или Gmail – и всё больше в WhatsApp. CRM, который не видит этих разговоров, остаётся пустым. Odoo подключается ко всем трём двумя способами: как почтовый сервер (Odoo отправляет и получает через ваш ящик, ответы попадают в нужный лид или предложение) и как боковая панель в почтовой программе (из письма одним кликом создать контакт или лид в Odoo).

Что мы проверили: все модули ниже ставятся в Odoo 18 Community – мы установили их в тестовой базе. Подключение настоящих аккаунтов Microsoft, Google и Meta описано по официальной документации Odoo и OCA; где что-то работает только на Odoo Online, это отмечено.

До начала (свой сервер)

  • HTTPS с постоянным именем – Microsoft и Google возвращают только на точно зарегистрированный адрес. Подойдёт любое публичное HTTPS-имя (ваш домен или для тестов бесплатное имя вроде nip.io).
  • Заморозить web.base.url – иначе Odoo ставит адрес последнего входа администратора, и OAuth-переадресация перестаёт совпадать.
  • Настройки ‣ Общие настройки ‣ Электронная почта ‣ Свои почтовые серверы – только тогда появляются поля для данных Outlook / Gmail.
  • Чей ящик? Один общий ящик (info@, vertrieb@) для Odoo проще, чем по ящику на пользователя, – и прав нужно меньше.

Ящик Outlook / Microsoft 365

  1. Azure: Microsoft Entra ID ‣ Регистрация приложений ‣ Создать: имя «Odoo», типы учётных записей «мультитенант + личные», платформа Web, URI перенаправления как выше.
  2. Разрешения: API permissions ‣ Microsoft Graph ‣ Delegated: SMTP.Send, IMAP.AccessAsUser.All.
  3. Пользователи: корпоративное приложение ‣ Пользователи и группы ‣ добавить тех, кто отправляет из Odoo.
  4. Секрет: Certificates & secrets ‣ New client secret – сразу скопировать значение, выбрать самый долгий срок и записать дату окончания в календарь: истечёт – почта встанет.
  5. Odoo: установить «Microsoft Outlook»; Настройки ‣ Общие ‣ Свои почтовые серверы ‣ Outlook Credentials: Client ID и значение секрета.
  6. Исходящий сервер: Настройки ‣ Технические ‣ Исходящие почтовые серверы ‣ Создать ‣ Outlook, имя пользователя, фильтр «От» (ваш домен) ‣ Connect your Outlook account ‣ Проверить соединение.
  7. Входящий сервер: Настройки ‣ Технические ‣ Входящие почтовые серверы ‣ Создать ‣ Outlook OAuth Authentication ‣ подключить ‣ проверить. Ответы на письма из Odoo теперь попадают в нужный лид или предложение.

Ящик Gmail / Google Workspace

  1. Google Cloud: новый проект «Odoo»; экран согласия OAuth: Internal (Workspace) или External (личный Gmail); при External в режиме тестирования добавить ящик в Test users.
  2. Credentials ‣ Create credentials ‣ OAuth client ID ‣ тип Web application (не Desktop – будет «redirect_uri_mismatch») ‣ URI перенаправления как выше.
  3. Odoo: установить «Google Gmail»; Настройки ‣ Общие ‣ Свои почтовые серверы ‣ Gmail Credentials: Client ID и Secret.
  4. Исходящий сервер: Создать ‣ Gmail OAuth Authentication ‣ Connect your Gmail account ‣ «Gmail Token Valid» ‣ Проверить соединение.
  5. Входящий сервер: так же с Gmail OAuth на входящем сервере.
  6. 403 access denied обычно значит, что ящика нет среди тестовых пользователей; статус «Production» даёт предупреждение о лимите 100 входов – Odoo советует оставаться в тестовом режиме.

Боковая панель: плагин для Outlook и Gmail

Плагин показывает рядом с письмом контакт и компанию из Odoo, открытые лиды и тикеты и одним кликом создаёт из письма лид. Со стороны Odoo: Настройки ‣ Общие настройки ‣ Интеграции ‣ Mail Plugin (для лидов поставить crm_mail_plugin).

  • Outlook: надстройка ставится из файла манифеста и затем входит в *вашу* базу по URL – это работает и со своим сервером на HTTPS. Если панель пустая, браузер блокирует сторонние cookies: разрешите cookies для download.odoo.com.
  • Gmail: «Odoo Inbox Addin» из Google Workspace Marketplace подключается только к *.odoo.com. Для своего сервера плагин надо взять из GitHub-репозитория Odoo mail-client-extensions, сменить разрешённый домен на свой и опубликовать как собственный проект Google Apps Script – реально, но это маленький отдельный проект.
  • Company insights (обогащение данных компании по домену письма) требуют платных IAP-кредитов; остальной плагин – нет.

WhatsApp

WhatsApp в Odoo работает через WhatsApp Business Platform Meta (API), а не через приложение WhatsApp Business на телефоне. Требования в обеих редакциях: бизнес-аккаунт Meta, приложение разработчика Meta с продуктом WhatsApp, зарегистрированный там номер и одобренные шаблоны сообщений для переписки, которую начинает компания. Meta берёт плату за разговор по своему прайсу.

  • Enterprise: приложение WhatsApp – WhatsApp ‣ Настройка ‣ WhatsApp Business Accounts: Phone Number ID, access token, App ID, Account ID, App Secret ‣ Test Connection; Callback URL и Verify Token скопировать в настройки вебхука у Meta; синхронизировать шаблоны. Отправлять из Odoo предложения, счета и напоминания в WhatsApp.
  • Community: OCA mail_gateway_whatsapp (OCA/social, ветка 18.0): Настройки ‣ Электронная почта ‣ Mail Gateway ‣ новый шлюз типа WhatsApp с токеном, Phone Number ID и секретом; вебхук у Meta вносится вручную. Чаты идут в Odoo Discuss – удобств меньше, чем в Enterprise, зато без лицензии.
  • Сервер должен быть доступен для Meta (вебхук по HTTPS).
  • DSGVO: деловые сообщения идут через Meta; нужно согласие клиента на WhatsApp и договор обработки данных с Meta (условия WhatsApp Business). Решить до первого сообщения.

Ловушки

  • Изменился web.base.url → ошибка OAuth «redirect URI mismatch» после входа администратора по другому адресу. Заморозить.
  • Истёк client secret (Azure) → почта тихо останавливается. Запись в календаре, мониторинг очереди писем.
  • Фильтр «От» / отправитель: Microsoft 365 и Gmail отправляют только от подключённого ящика (или разрешённых алиасов). Настройте фильтр «От» исходящего сервера и отправителя по умолчанию, иначе письма вернутся.
  • Личный или общий ящик: серверы на каждого пользователя требуют прав на настройки у этих пользователей и запасной сервер для уведомлений – начните с одного общего ящика.
  • Плагин Gmail на своём сервере – планировать как маленький проект, а не клик.
  • WhatsApp – без одобренных шаблонов можно отвечать только в течение 24 часов после последнего сообщения клиента.

Вывод

Outlook и Gmail как почтовые серверы и панель в Outlook полностью работают в Odoo Community на своём сервере; панель в Gmail требует там дополнительной работы, WhatsApp встроен в Enterprise и доступен в Community через OCA. Порядок, который мы советуем: заморозить адрес, подключить один общий ящик, настроить алиас для лидов, потом плагин для продаж, WhatsApp – последним. Мы настраиваем это для компаний в Германии, Австрии и Швейцарии и можем сначала показать на тестовой базе.
