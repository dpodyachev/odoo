Логи Odoo: warn или warning, log_level или --log-level? Шпаргалка

Конфиг, командная строка, click-odoo-update – три написания и три вида уровней. Одна таблица, чтобы подглядывать, и ошибки, при которых Odoo молча остаётся на INFO.

Сам постоянно забываю: warn или warning? log_level или log-level? Ответ зависит от того, где это пишешь. Всё на одной странице (проверено по коду Odoo 17).

Простое правило

  • В odoo.conf – подчёркивание: log_level, log_handler, log_db_level.
  • В командной строке – дефис: --log-level, --log-handler, --log-db-level.
  • log_level принимает собственные слова Odoo, строчными: warn (не warning!), error, info, debug …
  • log_handler ждёт уровни Python ЗАГЛАВНЫМИ: WARNING, ERROR, DEBUG.
  • log_db_level ждёт уровни Python строчными: warning, error (по умолчанию warning).

Шпаргалка

В базу данныхlog_db = %d, log_db_level = warning--log-db=%d --log-db-level=warningчерез -c
Сокращения–--log-sql, --log-web–

Допустимые значения

ПараметрЗначения
log_levelinfo (по умолчанию), warn, error, critical, debug, debug_sql, debug_rpc, debug_rpc_answer, notset, test, runbot
log_handlerPREFIX:УРОВЕНЬ, уровень = DEBUG · INFO · WARNING (или WARN) · ERROR · CRITICAL; пустой префикс = корневой логгер, напр. :INFO
log_db_leveldebug · info · warning · error · critical
log_db%d = текущая база или имя отдельной базы для логов

Примеры

click-odoo-update (и другие скрипты click-odoo) имеют собственные ключи --log-level и --logfile с теми же значениями, что и Odoo. Настройки отдельных логгеров берутся из конфига, переданного через -c.

Тихие ошибки

Командная строка сразу ругается на неправильное значение (invalid choice: 'warning'). Конфиг – нет: Odoo просто работает дальше на INFO, а ты удивляешься, почему лог такой большой:

log_level = warn ставит WARNING только логгерам odoo и werkzeug. Сторонние библиотеки продолжают писать INFO через корневой логгер. Для совсем тихого лога добавьте log_handler = :WARNING.
