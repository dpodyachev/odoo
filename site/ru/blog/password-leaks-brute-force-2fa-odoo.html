Пароли утекли? Как проверить – и как защитить Odoo от перебора, с 2FA

Где проверить, есть ли e-mail и пароль в утечках, не раскрывая сам пароль, и что умеет сам Odoo: тормоз логина, длина пароля, двухфакторный вход, API-ключи, fail2ban.

Есть ли мой адрес в утечке?

  • Have I Been Pwned – вводите e-mail и видите, в каких известных утечках он есть. Для своих доменов есть поиск по домену с уведомлениями.
  • Mozilla Monitor – те же данные с постоянным мониторингом по почте.
  • Google Password Checkup – проверяет пароли, сохранённые в Chrome / аккаунте Google.

Есть ли пароль в утечках – не раскрывая его?

API Pwned Passwords работает по принципу k-анонимности: отправляются только первые 5 символов SHA-1-хеша, сервер возвращает все окончания хешей с этим началом, а сравнение происходит локально. Сам пароль никогда не покидает компьютер.

Никогда не вводите пароли в любые формы «надёжен ли мой пароль?» в интернете. Безопасны – метод k-анонимности выше или менеджер паролей со встроенной проверкой утечек (Bitwarden, 1Password, KeePassXC).

Odoo: что уже встроено

Тормоз логина. После 5 неудачных попыток с одного IP-адреса Odoo ждёт 60 секунд, прежде чем проверить следующий вход оттуда. Оба значения меняются в системных параметрах. Счётчик ведётся отдельно в каждом процессе Odoo, так что при нескольких воркерах защита мягче, чем кажется по цифре.

  • Минимальная длина пароля: модуль auth_password_policy (параметр выше, например 12).
  • Двухфакторный вход (2FA): модуль auth_totp – каждый пользователь включает его в своих настройках через приложение-аутентификатор. С auth_totp_mail_enforce его можно сделать обязательным в общих настройках: только для сотрудников или для всех.
  • API-ключи вместо паролей для интеграций (настройки пользователя → Безопасность учётной записи). Ключ можно отозвать отдельно, и 2FA не блокирует интеграцию.
  • Переименуйте пользователя admin или используйте свой логин: admin перебирают первым.

fail2ban: блокировать атакующих на уровне сети

Odoo пишет в лог каждую попытку входа вместе с IP-адресом:

fail2ban превращает это в блокировку в файрволе. Условия: log_level не ниже info (эти сообщения имеют уровень INFO) и proxy_mode = True за nginx, иначе в логе будет IP nginx.

Чек-лист

  • Менеджер баз закрыт, list_db = False (см. статью про nginx/Apache).
  • 2FA обязательна для всех внутренних пользователей.
  • Минимальная длина 12+, менеджер паролей для команды.
  • Тормоз логина включён, плюс limit_req в nginx или fail2ban.
  • Интеграции – с API-ключами, а не с паролями пользователей.
  • Домен компании – под мониторингом Have I Been Pwned.

Инструменты и документация

  • Have I Been Pwned
  • Pwned Passwords API (k-anonymity)
  • Mozilla Monitor
  • Google Password Checkup
  • Odoo 17: Two-factor authentication
