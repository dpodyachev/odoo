Odoo в docker-compose: extra-addons, odoo.conf и nginx – в контейнере или на хосте

Как правильно смонтировать свои и OCA-модули, что должно быть в odoo.conf и как nginx корректно проксирует Odoo вместе с websocket – в обоих вариантах.

Odoo в docker-compose запускается быстро, а типичные проблемы начинаются потом: модули не появляются, изменения конфига не действуют, чат не подключается, или Odoo вдруг доступен напрямую из интернета. Вот схема, которая себя оправдала.

Структура каталогов

docker-compose.yml

  • Монтируйте каталоги, а не отдельные файлы. Если смонтирован только файл odoo.conf, контейнер не увидит изменений после sed -i или редактора, который перезаписывает файл: у нового файла другой inode. С ./config:/etc/odoo этой проблемы нет.
  • Модули монтируйте с :ro: Odoo не нужны права на запись туда.
  • Официальный образ работает от пользователя odoo (UID 101). Для bind-mount с данными: chown -R 101:101.

odoo.conf

  • В addons_path пишутся пути внутри контейнера, а не на хосте.
  • OCA-репозиторий – это каталог со многими модулями. Каждый репозиторий нужно указать отдельно, родительского oca/ недостаточно.
  • Новые модули появляются только после перезапуска и «Приложения → Обновить список» (или -u base). Без __manifest__.py в каталоге это не модуль.
  • proxy_mode = True за nginx обязателен, иначе Odoo видит http вместо https и IP nginx вместо клиента.

nginx: один конфиг, два варианта

Odoo 17 нужны два адреса: 8069 для всего и 8072 для /websocket (чат, уведомления). Конфиг одинаковый в обоих вариантах, отличаются только адреса в upstream.

Вариант А: nginx в том же docker-compose

nginx обращается к Odoo по имени сервиса odoo в сети compose. Odoo не публикует порты, снаружи виден только nginx на 80/443. Сертификаты берутся с хоста (/etc/letsencrypt, только чтение).

Вариант Б: nginx на хосте

Порты Odoo публикуются только на 127.0.0.1 (см. закомментированные ports выше), а в upstream nginx указываются 127.0.0.1:8069 и 127.0.0.1:8072.

Внимание: "8069:8069" без 127.0.0.1 открывает Odoo всему интернету, даже если ufw блокирует порт. Docker пишет свои правила прямо в iptables, в обход ufw.
